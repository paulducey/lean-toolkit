A question for the room

Last week, how many hours did you spend at a keyboard producing documents about the gemba?

  • A3Drafting, reformatting, re-drafting for the steering committee
  • OEEWrestling a downtime export into a spreadsheet
  • SWTyping up a standard work sheet from your notes
  • RCATurning a 5 Whys whiteboard into a report someone will read

Where those hours come from

Every one of them is an hour not at the gemba. The document is necessary. The keyboard time is not value-added — it's the transportation and motion waste of the CI function itself.

Design principle 1 of 5

Jidoka for information.

Every number carries a source tag. An untagged number is a defect passed downstream — so there aren't any.

Jidoka: build quality in, stop rather than pass a defect. The biggest real danger of these tools is a confident-sounding number with no provenance. So the rule is: every figure says where it came from, and if it came from nowhere, the assistant says so — in yellow.

Design principles 2, 3, 4 of 5 · fast

Three more, written into the standard work.

Poka-yoke for data

Missing column? It says which — never substitutes a value. Reason code it can't map? An explicit Unmapped row. OEE over 100%? Flagged, not printed — your "ideal" cycle time is probably an average.

Observe, don't solve

The gemba-walk skill asks "what makes this step difficult?" — never "why aren't you following the standard?" It will not hand you a punch list. A walk that only produces corrections is an inspection.

Sensei first, draft on demand

Coaching skills ask before they draft, left-to-right on the A3. Say "just draft it" and you get a draft in seconds — every unknown fact marked [NEEDS GEMBA], never invented.

Respect for people, written in.

  • 01Ask it "how many people can we cut" and it answers the process question — then says once, plainly: these tools free capacity; what the organization does with freed capacity is a leadership decision.No lecture. No refusal. But it will not do that math for you as if it were neutral.

Where it goes wrong · and how to start anyway

Same tool. Opposite outcomes. The difference is a habit.

It goes wrong when

  • The practitioner stops going. It amplifies the one who goes and sees; it hollows out the one who doesn't.
  • You read the tone, not the tags. It always sounds confident. Confidence is not a source.
  • Confidential data in a chat box. Know your company's policy before the first paste.

Start like you'd start anything

  • One practitioner who already goes to the gemba. Never the one who doesn't — you'll just get more documents.
  • One skill, one live problem, two weeks. Not a pilot.
  • One measure: did hours at the gemba go up? Not "did we use AI." If no — stop. It's a clipboard, not a strategy.
