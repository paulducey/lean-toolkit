# OEE input shape

One row per production event (a shift/day/line total, plus one row per
downtime event). CSV; comma, semicolon, or tab all work. A junk title row
above the header (e.g. "Line 1 — Downtime Export — generated by MES") is
tolerated and skipped automatically, and blank columns are dropped. Column
names are matched loosely by alias, case-insensitively.

## Required columns

| Column | Accepts (aliases) | Meaning |
|---|---|---|
| `planned_min` | `planned_time`, `planned_production_time`, `planned time (min)`, `scheduled_min`, `scheduled hours` | Planned production time for the period, in minutes |
| `ideal_cycle_time` | `ideal_cycle_time_min`, `ideal cycle time`, `rated_speed`, `cycle_time` | Best-demonstrated time per unit, in minutes (use `--cycle-time-unit s` if the export gives seconds) |
| `total_count` | `total`, `units`, `count`, `produced`, `total units` | Total units (or scans, or visits) produced in the period |

If any of these three is missing, the script prints exactly what it found
and what it still needs — it never estimates a substitute value.

## Optional columns

| Column | Accepts (aliases) | Meaning |
|---|---|---|
| `good_count` | `good`, `good units`, `first_pass` | Units that were good the first time |
| `reject_count` | `rejects`, `scrap`, `reject` | Units rejected (used to derive good count if `good_count` is blank) |
| `downtime_min` | `downtime`, `duration_min`, `duration`, `downtime (min)` | Length of one downtime event, in minutes — one row per event |
| `downtime_reason` | `reason`, `reason_code`, `cause`, `downtime reason` | Free-text reason, matched by keyword into the Six Big Losses |
| `planned_downtime` | `is_planned`, `planned` | `1`/`true`/`yes`/`planned` marks a downtime row as planned (breaks, scheduled changeover, PM) — excluded from the Availability loss |
| `date`, `shift`, `line` | `day`; — ; `machine`, `asset`, `cell`, `room` | Grouping columns — when present, the report adds a per-day/shift/line breakdown |

Neither `good_count` nor `reject_count` present at all → Quality is
omitted and the result is reported as A × P, never called OEE. A blank
`good_count`/`reject_count` cell on a row that otherwise has data is
excluded from Quality and named in the report — never treated as 100% good.

## Units

`ideal_cycle_time` is assumed to be in **minutes**. If your export gives it
in seconds, add `--cycle-time-unit s` to the command — don't convert the
column by hand first.

## Example (messy real-world export)

```
Line 1 - Downtime Export - generated by MES 2026-09-12 06:02
date,shift,line,planned_min,ideal_cycle_time_min,total_count,good_count,reject_count,,downtime_reason,downtime_min
2026-09-11,1,Line 1,480,0.5,720,691,29,,Press fault - hydraulic,18
2026-09-11,1,Line 1,,,,,,,Breakdown - feeder motor,13
```

The title row and the blank column between `reject_count` and
`downtime_reason` are both tolerated automatically.
